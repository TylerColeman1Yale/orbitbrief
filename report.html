OrbitBrief

A source-backed orbital briefing studio that turns a dated public catalog into an explorable 3D Earth, reproducible filters, modeled satellite motion, and evidence-aware answers.

Executive claim

OrbitBrief is designed for a university space-club member, educator, or policy student who needs to explain the orbital environment without manually joining orbital elements, catalog metadata, and agency explanations. 1. Motivation: a fragmented explanation task

Orbital-sustainability explanations look simple until a student tries to answer one question carefully. “How many objects are between 500 and 800 km?” may require a catalog, object-type definitions, orbital propagation, an altitude convention, a date, and a warning that the result is not a count of every object in space. A launch or debris question adds another source and another definition boundary.

Primary user

The first user is a university space-club member, educator, or policy/research student preparing a briefing. They need to make a complicated environment understandable to a non-specialist and show where each number came from. Their current workflow is typically a mixture of CelesTrak pages, agency explainers, spreadsheets, screenshots, and manually written notes.

Why the problem matters

Time cost
Manual joining of orbital records and explanatory sources makes even a basic count difficult to reproduce.
Meaning cost
Payload, debris, rocket body, operational status, launch event, and estimated fragment population are easy to conflate.
Trust cost
A polished globe can imply precision or collision prediction unless freshness, coverage, and uncertainty are visible.
Teaching cost
A static answer does not let a learner rotate the Earth, inspect an object, or see how time changes the modeled scene.
Design goal: make the analytical definition and the visual scene agree, while keeping the data date and coverage visible beside the answer.

Impact evidence is not fabricated; this report does not include independent user-study results.

2. What is new, and what is not

OrbitBrief does not claim to be the first globe, orbital catalog, or space chatbot. CelesTrak provides orbital elements and SATCAT metadata. KeepTrack provides a sophisticated public orbital visualization. NASA Orbital Debris and NASA CARA provide authoritative educational and operational context. Those products establish the baseline rather than disappear from the comparison.

Existing referenceWhat it already doesOrbitBrief's different emphasis
CelesTrakPublic orbital elements, groups, and catalog metadata.Turns a pinned snapshot into a beginner-friendly, visible question-to-filter workflow.
KeepTrackAdvanced interactive tracking and visualization.Optimizes for a cited educational briefing, not operational tracking depth.
NASA Orbital DebrisAgency explanations and debris context.Links explanatory limits to the exact catalog view and object types on screen.

The differentiating hypothesis

Honest boundary: this is an educational/research exploration tool, not a conjunction-avoidance or collision-probability system.

3. Product walkthrough

The finished local app is intentionally compact: a catalog-control rail, a WebGL Earth and orbital scene, a UTC simulation bar, and a bounded Analyst panel. The user can use controls directly or ask for a reversible filter action in natural language.

Explore

Rotate the globe in every direction, zoom, toggle the dimmed backside, and click an object for its NORAD ID, type, status, modeled altitude, inclination, epoch, and source context.

Filter

Search name/NORAD ID, choose payload/debris/rocket body/unknown, select purpose, and enter an altitude band. Counts use the same semantics as the scene.

Simulate

Play/pause a UTC clock, select a presentation speed, advance an hour, and return to the snapshot time. Real OMM records are propagated with satellite.js SGP4 on the server.

Ask

Ask about object types, purpose counts, regions, debris removal, historical collisions, or collision-assessment limits. High-confidence numeric actions are deterministic.

Evidence behavior

The application exposes the implemented path and its source/evidence behavior directly in the interface, including deterministic results, source citations, and explicit limitations.

The user-provided visual feedback drove the final globe alignment, full rotation, synchronized Earth/satellite transforms, closeable object cards, slow propagation, and the filter-action repair.

4. Agent design and architecture

OrbitBrief uses one bounded Analyst path rather than multiple agents for appearance. The server owns the catalog boundary. Deterministic JavaScript performs propagation, filters, counts, evidence, region queries, and scene patches. The optional Portkey call handles general explanatory language after deterministic intents have been checked.

5. One real run and evidence chain

A representative run is the natural-language purpose filter. The user asks “Filter to navigation satellites.” The server recognizes the purpose and filter intent, counts the matching records in the pinned snapshot, returns an action patch, and the browser applies Purpose = Navigation. This is the same state a user would get from the left dropdown.

1 · Intent

Purpose = navigation; requested action = filter/show only.

2 · Query

Count records whose source-backed heuristic purpose list includes navigation.

3 · Result

154 cataloged navigation-purpose objects in snapshot `celestrak-groups-2026-10-24`.

4 · UI action

Set the purpose control to Navigation, re-render the globe, update cards, and request verified positions.

Evidence fields: dataset ID, simulation time, source URL, retrieval date, purpose-tag limitation, matched count, and a reversible filter patch.

Other deterministic paths

  • Altitude queries use instantaneous modeled altitude and `[low, high)` boundaries.
  • Weather/science/communications/navigation/earth-observation counts are source-backed catalog tags, not claims about every object in orbit.
  • Collision-probability requests explain the missing covariance, miss-distance, time-of-closest-approach, and validated probability method.
  • General questions can use the provider model, but the app never presents provider prose as live telemetry.
Example evidence path: the navigation filter applies the Purpose control, then a follow-up question returns the deterministic tool trace, dataset ID, and source citation.

7. Safety and security

OrbitBrief's most important safety risk is not an attacker making the globe ugly; it is a user mistaking a polished visualization or generated explanation for operational space-safety advice.

8. Data validity and scientific limits

Snapshot facts

10

154
navigation-purpose tags

The snapshot combines named CelesTrak groups: active objects, three named debris groups, and last-30-days additions, with SATCAT metadata. It is not a full catalog. Purpose tags are partly name-based. A payload's operational status is not the same dimension as physical object type.

Propagation

Real OMM records are propagated with satellite.js 7.1.0 SGP4, then converted to geodetic latitude, longitude, and altitude. The globe and markers share a documented yaw/pitch frame, so rotating the Earth preserves geographic alignment. The displayed simulation is an educational projection from the latest element snapshot; it does not know future maneuvers, live telemetry, reentries, or actual collisions.

Launches and debris

The Launches tab is an offline fixture-backed explanation and should not be described as a live launch feed. The app separates cataloged debris from agency estimates for smaller untracked fragments. The historical Iridium 33/Cosmos 2251 explanation is curated and nonexhaustive.

Interpretation rule: “154 navigation objects” means 154 records in this snapshot whose heuristic purpose tags include navigation. It does not mean 154 active navigation satellites in all of space.

Appendix A · Reproduction and demonstration sequence

Reproduce the briefing

OrbitBrief is designed to be run locally with Node.js 20 or newer. The complete numbered setup is in README.md; the short path is:

  1. Open Terminal in the project folder.
  2. Run npm install.
  3. Optionally copy .env.example to .env for the Portkey general-answer path.
  4. Run npm start and open http://127.0.0.1:4173.
  5. Use Control-C in the server Terminal to stop the app.

Demonstration sequence

Explore
Rotate the full 3D Earth, zoom, reveal the backside, and select a marker.
Filter
Ask “filter to navigation satellites” and show the Purpose control plus the updated count.
Continue
Ask “How can debris be removed?” followed by “Is it worth it?” to show conversational context and citations.
Simulate
Press play, change speed, advance the UTC clock, and show markers moving from propagated positions.

Reproducible evidence

The bundled snapshot is identified as celestrak-groups-2026-10-24. Deterministic actions return a dataset ID, time, tool trace, coverage note, and source links. The verification commands are npm test, npm run validate, and npm run build.
